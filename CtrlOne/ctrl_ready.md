# 프로젝트 개요
Windows 환경에서 구동되는 단일 실행 파일(.exe) 형태의 **Blackmagic HyperDeck 가변형 동시 제어 및 실시간 모니터링 웹 대시보드 애플리케이션** 개발을 요청합니다. 
C# 지식이 있는 사용자가 유지보수하기 좋게 클린 코드로 작성해 주시고, 실행 시 백전에서 내장 웹서버가 구동되며 자동으로 기본 브라우저 창이 열려 대시보드 UI를 바로 사용할 수 있도록 통합해 주세요.

## 1. 기술 스택 및 구조
- **언어 및 프레임워크**: C# / .NET 8 / ASP.NET Core (Minimal API + Blazor Server 또는 Static HTML/JS/SignalR)
- **배포 형태**: 종속성이 단일 파일에 포함되는 단일 실행 파일 (Single File Executable, .exe)
- **데이터 보존**: 사용자가 UI에서 추가/수정/삭제/순서 변경한 장비 리스트 정보는 프로그램 종료 후에도 유지되도록 로컬 설정 파일(`devices.json`)에 자동 저장/로드되어야 합니다.

## 2. 핵심 UI/UX 요구사항 (웹 브라우저 대시보드)
화면은 반응형 웹 단일 페이지(Single Page Dashboard)로 구성하며 다음 세 영역을 포함합니다.

### A. 상단 영역: 선택형 그룹 일괄 제어 및 장비 추가
- **장비 추가 버튼 & 팝업/폼**: 사용자가 [장비 추가] 버튼을 누르면 `장비 IP 주소`와 `사용자 정의 이름 (예: Mini_Camera_01)`을 입력하여 새로운 HyperDeck 장치를 리스트에 등록할 수 있어야 합니다.
- **장비 선택 토글 시스템**: 등록된 모든 장비 각각을 그룹 제어 대상에 포함할지 선택하는 Toggle 스위치/체크박스 제공.
- **일괄 녹화 시작 버튼**: 토글이 '켜짐' 상태인 장비들에게만 동시에 `record` 명령을 전송.
- **일괄 녹화 중지 버튼**: 토글이 '켜짐' 상태인 장비들에게만 동시에 `stop` 명령을 전송.

### B. 중단 영역: 동적 장비 카드 리스트 (모니터링, 제어, 순서 변경)
- 등록된 장비 개수에 따라 UI 카드가 화면에 그리드 형태로 **유연하게 늘어나거나 줄어들도록(동적 렌더링)** 구현해 주세요.
- **순서 변경 기능 (요구사항 추가)**: 각 장비 카드에 [▲ 위로], [▼ 아래로] 버튼(또는 드래그 앤 드롭)을 배치하여 **대시보드 상의 장비 출력 순서를 실시간으로 변경**할 수 있어야 합니다. 이 변경된 정렬 순서는 `devices.json`에 즉시 반영되어 다음 실행 시에도 유지되어야 합니다.
- **사용자 정의 이름**: 각 카드 상단에 사용자가 지정한 이름과 설정된 IP 주소를 명확히 표시하고, UI에서 이름을 즉시 수정(Rename)할 수 있는 편집 버튼을 제공해 주세요.
- **장비 삭제 기능**: 각 카드 우측 상단에 [X] 또는 [삭제] 버튼을 두어, 해당 장비의 소켓 연결을 안전하게 종료하고 대시보드 및 리스트에서 완전히 제거할 수 있도록 해주세요.
- **연결 상태 및 모니터링**: TCP 소켓 연결 여부 실시간 인디케이터 (Connected: 초록 / Disconnected: 빨강) 및 각 슬롯(Slot 1 & Slot 2)의 미디어 상태와 남은 녹화 가능 시간(`02:45:12`) 실시간 표시.
- **개별 제어 버튼**: 장비별 독립적인 [▶ 재생], [🔴 녹화], [⏹️ 중지] 버튼 제공.

### C. 하단 영역: 실시간 통합 로그 창
- 화면 하단에 모든 장비와의 데이터 송수신(Tx/Rx) 내역 및 연결 이벤트 로그를 실시간으로 출력하는 **전용 텍스트 영역(Log Terminal View)**을 배치해 주세요. 로그가 추가되면 자동으로 가장 아래로 스크롤(Auto-scroll)되어야 합니다.

## 3. 백엔드 통신 아키텍처 및 Companion 참고 지침 (안정성 확보)
- **통신 방식**: 포트 9993을 사용하는 TCP 이더넷 제어 프로토콜.
- **가변 멀티 소켓**: 동적으로 추가되는 장비마다 독립적인 `TcpClient` 연결 스레드를 생성하고 관리해야 합니다. UI와 통신 스레드가 차단되지 않도록 `async/await` 및 `Task` 기반으로 완전히 비동기 처리해 주세요.
- **안정성을 위한 오픈소스 Companion 코드 참고**:
  - HyperDeck의 TCP 데이터 스트림이 분할되어 들어올 때 데이터 누락이나 엉킴이 없도록, `StringBuilder` 등을 활용해 문장 종결자(`\n`) 기준으로 버퍼를 쪼개어 파싱하는 Companion의 버퍼링 방식을 C#으로 이식해 주세요.
  - 연결 끊김 발생 시 5초 주기로 자동 재연결(Keep-Alive)하는 안정성 로직을 구현해 주세요.
  - 연결 직후 실시간 이벤트를 수신하기 위해 `notify: transport: true slot: true\n` 시퀀스를 반드시 전송해 주세요.

## 4. 확장성 고려 사항 (AverMedia 장비 장기 계획)
- `ISequenceDevice` 같은 공통 인터페이스를 정의하고, HyperDeck 클래스가 이를 상속받아 구현하는 구조로 코드를 설계하여 향후 타사 기기 확장이 쉽도록 아키텍처를 잡아주세요.

## 5. 단계별 구현 및 문서화 요청 (요구사항 추가)
코딩 진행과 함께 다음 단계를 순서대로 완수해 주세요.
1. **1단계 (통신)**: `ISequenceDevice` 인터페이스 및 순서 관리가 가능한 동적 `HyperDeckService.cs` 클래스 빌드.
2. **2단계 (저장 및 연동)**: 장비 추가/삭제/이름 변경/순서 조정 시 `devices.json`에 정렬 인덱스를 반영하는 로직 및 웹 UI 푸시(SignalR) 연동.
3. **3단계 (UI 및 진입점)**: 순서 변경 버튼이 포함된 그리드 형태의 대시보드 웹 UI 디자인 및 전체 진입점(.exe 실행 시 브라우저 자동 오픈) 코드 완성.
4. **4단계 (문서화)**: 프로젝트 루트 폴더에 아래 두 가지 마크다운 문서를 상세히 작성해 주세요.
   - `README.md` (사용자 설명서): 프로그램 실행 방법, UI를 통한 장비 추가/삭제/순서 변경/일괄 제어 사용법 기술.
   - `DEVELOPER.md` (개발자 문서): 프로젝트 아키텍처, `ISequenceDevice` 인터페이스 구조, Companion의 TCP 버퍼 파싱 구현 방식, 추후 AverMedia 등 타사 장비 확장 시 플러그인 추가 방법 기술.
