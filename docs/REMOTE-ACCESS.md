# 방송실 앱 — 외부·다중 단말기 접속 가이드

방송실 스위트(`BroadcastNasBridge` + 일정·일지·파일체크)를  
**집 밖 인터넷에서도**, **PC / Mac / 스마트폰**으로 쓰려면 무엇이 필요한지 정리한 문서입니다.

## 한눈에 보기

| 질문 | 짧은 답 |
|------|---------|
| 지금 구조만으로 폰에서 바로 되나? | **안 됨** (브리지가 그 PC의만 열림) |
| NAS 외부 주소만 넣으면 되나? | **PC에 브리지를 켠 경우** SMB 상대로는 가능. **폰·아무 기기**용은 아님 |
| 가장 현실적인 1순위 | **상시 PC(또는 미니 PC) + VPN** |
| 시놀로지만으로 지금 브리지를 돌리기 | **당장 비추천** (앱이 Windows/Mac SMB 전제, Docker용으로 아직 안 맞춰짐) |
| 브라우저 URL만으로 공개 | **상시 브리지 + HTTPS + 로그인** 추가 작업 필요 |

## 1. 지금 앱이 동작하는 방식

어려운 말부터 풀어 쓰면 다음과 같습니다.

```text
[단말기 브라우저]  --HTTP-->  [브리지 프로그램]  --SMB-->  [NAS 파일]
   (화면)              (중간 서버)              (실제 저장소)
```

| 용어 | 쉬운 설명 |
|------|-----------|
| **브리지 (BroadcastNasBridge)** | NAS와 브라우저 사이를 잇는 **중간 프로그램**. 파일을 직접 만지고, 화면용 API를 제공합니다. |
| **HTTP** | 브라우저가 웹페이지·API를 주고받을 때 쓰는 통신 방식. 주소는 보통 `http://…` |
| **SMB** | Windows에서 `\\나스주소\공유폴더` 로 파일을 열 때 쓰는 **파일 공유 프로토콜**. 나스와 PC가 “같은 폴더를 본다”고 생각하면 됩니다. |
| **localhost / 127.0.0.1** | “**이 컴퓨터 자기 자신**”만 가리키는 주소. 다른 폰·PC에서는 닿지 않습니다. |
| **포트 (예: 17820)** | 한 컴퓨터 안에서 여러 프로그램이 통신할 때 나누는 **문 번호**. 브리지는 `17820` 문을 사용합니다. |

**현재 기본 설정**

- 브리지는 `http://127.0.0.1:17820` **만** 듣습니다 → **그 PC의 브라우저만** 접속 가능  
- SMB는 보통 **내부망 NAS IP**로 연결  
- 스마트폰·다른 PC 브라우저는 이 브리지에 접속할 수 없음  

그래서 “내부 네트워크의 그 PC에서만” 잘 되는 것이 정상입니다.

## 2. 질문에 대한 답: 상시 브리지를 어디에 둘까?

지금은 **상시 가동 브리지가 없는 상태**입니다.  
밖에서 쓰려면 **항상 켜져 있는 “중간 서버” 역할**이 어딘가에 필요합니다.

### 선택지 비교

| | **A. 브리지용 PC (또는 미니 PC) 상시 가동** | **B. 시놀로지 NAS에서 브리지 자체 실행** |
|--|---------------------------------------------|------------------------------------------|
| **지금 코드와의 궁합** | **맞음** (Windows/Mac용으로 이미 동작) | **안 맞음** — DSM/Docker용으로 아직 포팅·검증 없음 |
| **SMB 연결** | PC → NAS (내부 IP) — 지금과 동일, 안정적 | NAS 안에서 자기 디스크를 볼 수도 있으나, **앱 구조 변경**이 큼 |
| **전기·공간** | 미니 PC 하나 추가 | 추가 기기 없음 |
| **관리** | Windows 업데이트·전원·원격 켜기 정도 | DSM·Docker·권한·포트 — 익숙하면 편하지만 **초기 공수가 큼** |
| **성능** | 일정·일지 JSON에는 충분 | NAS CPU는 다른 서비스와 공유 |
| **추천** | **1순위 (지금 당장)** | **중장기 아이디어** (Docker 이미지·Linux SMB 지원 후) |

### 결론 (권장)

1. **당분간은 방송실에 작은 PC(또는 기존 PC)를 상시 켜 두고 브리지를 돌리는 쪽**이 낫습니다.  
2. 시놀로지는 이미 **파일 저장소 + (선택) VPN 서버 / 리버스 프록시**로 쓰는 편이 역할 분리가 좋습니다.  
3. “나스 하나에 다 넣기”는 매력적이지만, **현재 `BroadcastNasBridge`는 Synology 패키지/컨테이너로 나온 제품이 아닙니다.** 억지로 올리면 유지보수가 앱 개발 쪽으로 넘어갑니다.

**현실적인 구성 예**

```text
[시놀로지 NAS]     ← 파일만 보관, 가능하면 VPN도 여기 또는 공유기에
[상시 미니 PC]     ← BroadcastNasBridge만 항상 실행, NAS는 내부 IP로 SMB
[집 밖 폰/노트북]  ← VPN으로 들어온 뒤 브라우저로 브리지 접속
```

미니 PC 사양은 낮아도 됩니다. (절전·자동 로그인·브리지 시작프로그램 등록만 중요)

## 3. 질문에 대한 답: VPN vs HTTPS — 뭐가 있는지, 뭐가 좋은지

“밖에 나가서 쓰려면” 크게 **두 갈래**입니다.  
둘 다 “있는지 모르겠다”면, 아래를 읽고 **1순위로 VPN**을 고르면 됩니다.

### 용어 보충

| 용어 | 쉬운 설명 |
|------|-----------|
| **VPN** | 집(또는 방송실) 내부망으로 들어가는 **암호화된 터널**. 켜면 폰이 “그 건물 Wi‑Fi에 있는 것처럼” 동작합니다. |
| **WireGuard / OpenVPN** | VPN을 만드는 **구체적인 기술 이름**. 시놀로지·공유기·방화벽에서 지원하는 경우가 많습니다. |
| **HTTPS** | 자물쇠 걸린 웹 통신 (`https://…`). 비밀번호·일지 내용이 중간에 엿보이기 어렵게 합니다. |
| **리버스 프록시** | 인터넷에서 들어온 요청을 **안의 브리지로 대신 전달**해 주는 문지기 (Nginx, Caddy, 시놀로지 역방향 프록시 등). |
| **DDNS** | 집 인터넷 IP가 바뀌어도 `우리교회.예시도메인.com` 같은 **이름**으로 찾아가게 하는 서비스. |
| **포트 포워딩** | 공유기에서 “바깥의 443번 문은 안쪽 PC의 443으로”처럼 **문을 열어 주는** 설정. |
| **인증 (로그인)** | 아무나 URL을 알아도 못 들어오게 **아이디·비밀번호(또는 SSO)** 로 막는 것. |

---

### 방법 ① VPN (추천 · 1순위)

**아이디어:** 밖에서도 먼저 VPN으로 “내부망 입장” → 그다음 지금 앱을 (거의) 그대로 사용.

```text
[밖: 폰/노트북]
    │  VPN 연결
    ▼
[방송실 LAN]
    │
    ├─ 상시 PC의 브리지 (HTTP)
    └─ NAS (SMB는 내부만)
```

| 항목 | 내용 |
|------|------|
| **필요한 것** | VPN 서버(시놀로지·공유기·별도), 상시 브리지 PC, 단말에 VPN 앱 |
| **앱 수정** | 최소. (폰이 브리지 URL로 접속하려면 브리지를 `127.0.0.1`이 아니라 **LAN에서 받게** 바꾸는 작업은 필요) |
| **보안** | SMB·17820을 인터넷에 직접 안 열어도 됨 → **상대적으로 안전** |
| **사용감** | VPN 앱 켠 다음 브라우저. “사이트 북마크만”보다는 한 단계 많음 |
| **모바일** | Android/iOS VPN 앱 + 모바일 브라우저로 가능 (화면은 PC용 UI라 작을 수 있음) |

**이런 분에게 맞음**

- 외부 공개 웹사이트를 새로 운영하고 싶지 않은 경우  
- 보안·교회/방송실 데이터를 조심스럽게 다루고 싶은 경우  
- 일단 **빨리·적은 개발로** 밖에서 쓰고 싶은 경우  

**시놀로지에서 VPN을 쓰는 경우 (개념)**

1. DSM에서 VPN 서버(또는 Tailscale/WireGuard 패키지·커뮤니티 패키지) 활성화  
2. 사용자 계정·권한 생성  
3. 폰/노트북에 같은 종류 VPN 클라이언트 설치 후 접속  
4. 접속된 상태에서 상시 PC의 `http://내부IP:17820` 등으로 브리지 접속  
   - *지금은 브리지가 localhost만 허용하므로, LAN IP 접속을 쓰려면 **설정/코드 변경**이 선행되어야 합니다.*  
   - 변경 전에는 **원격 데스크톱으로 상시 PC에 들어가** 그 PC 브라우저로 쓰는 우회도 가능합니다.

---

### 방법 ② HTTPS로 웹 공개 (북마크만으로 접속)

**아이디어:** `https://broadcast.예시도메인.com` 처럼 **일반 웹사이트처럼** 열어, VPN 없이 브라우저만 사용.

```text
[밖: 아무 브라우저]
    │  HTTPS (443)
    ▼
[공유기/시놀로지 리버스 프록시]
    │
    ▼
[상시 PC의 브리지]
    │  SMB (내부)
    ▼
[NAS]
```

| 항목 | 내용 |
|------|------|
| **필요한 것** | 도메인(또는 DDNS), HTTPS 인증서, 리버스 프록시, **강한 로그인**, 상시 브리지, (보통) 포트 포워딩 |
| **앱 수정** | 중~대. listen 주소, 인증, 쿠키/HTTPS 전제, 모바일 UX 점검 등 |
| **보안** | URL이 새면 공격 대상. **반드시 인증 + HTTPS**. SMB는 밖으로 열지 말 것 |
| **사용감** | VPN 없이 편함. 폰·PC·맥 동일하게 브라우저 |
| **모바일** | 별도 앱 스토어 빌드 없이도 가능. 필요하면 홈 화면 추가(PWA) |

**이런 분에게 맞음**

- “VPN 앱 없이 링크만 공유하고 싶다”  
- 여러 사람이 **각자 폰**으로 자주 들어온다  
- 앞으로 **웹 서비스처럼** 운영할 의지가 있다  

**주의**

- NAS **외부 SMB 주소**를 인터넷에 여는 것과, **웹(HTTPS)** 을 여는 것은 다릅니다.  
- QuickConnect·DSM 웹 주소 ≠ 이 방송실 앱 주소입니다.  
- 브리지를 인증 없이 인터넷에 두면 **일정·일지·파일 목록이 유출**될 수 있습니다.

---

### 방법 ③ NAS 외부 주소로 SMB만 (제한적)

```text
[밖에 있는 내 노트북]
  브리지 실행 + 호스트에 NAS 외부주소
        --SMB over Internet-->  NAS
```

| 항목 | 내용 |
|------|------|
| **되는 것** | **그 노트북에 브리지를 설치·실행**한 뒤, 탐색기로도 SMB가 되는 환경 |
| **안 되는 것** | 폰만으로 사용, “아무 단말기 브라우저만” |
| **리스크** | SMB(주로 포트 **445**)를 인터넷에 열면 해킹 표적이 되기 쉬움. 통신사·ISP가 445를 막는 경우도 많음 |

→ “밖에 나간 **내 PC**에서만” 임시로 쓸 때의 옵션이지, **목표(어디서나·어떤 단말기)** 의 본안이 아닙니다.

---

### 방법 비교 요약

| | VPN | HTTPS 공개 | NAS 외부 SMB |
|--|-----|------------|--------------|
| 구현 난이도 (인프라) | 중 | 중~상 | 중 (되지만 위험) |
| 앱/코드 작업 | 소~중 | 중~대 | 거의 없음 (PC 한정) |
| 보안 | **우수** | 인증 잘하면 양호 | **비추천** |
| 폰 브라우저 | VPN 후 가능 | **가장 자연스러움** | 불가에 가까움 |
| 추천 순위 | **1** | **2** (편의 중시 시) | 임시·비권장 |

**추천 조합**

1. **지금:** 상시 미니 PC + **VPN** (+ 필요 시 브리지 LAN 공개)  
2. **나중에:** 같은 상시 PC 앞에 **HTTPS + 로그인**을 올려 “북마크만” 경험으로 확장  
3. 시놀로지: **저장소 + VPN(또는 프록시)** 역할, 브리지 실행은 PC 유지

## 4. 「어디서나 · PC/Mac/모바일」로 가는 전체 로드맵

목표를 달성하는 **권장 순서**입니다.

### 단계 0 — 목표 확정

- [ ] VPN으로 충분한가, 북마크(HTTPS)까지 필요한가  
- [ ] 누가 접속하나 (본인만 / 스태프 여러 명)  
- [ ] 상시로 둘 PC가 있는가 (없으면 미니 PC 구매 검토)

### 단계 1 — 상시 브리지 PC 준비

- [ ] 방송실에 PC 또는 미니 PC 배치, 절전 해제, 자동 로그인(정책에 맞게)  
- [ ] `BroadcastNasBridge` 시작프로그램 등록, NAS는 **내부 IP**로 연결  
- [ ] 내부에서 `/schedule` `/worklog` `/files` 정상 확인  

### 단계 2 — 외부 진입 수단 (VPN 권장)

- [ ] 시놀로지 또는 공유기에서 VPN 서버 설정  
- [ ] 테스트: 휴대폰 LTE + VPN → 내부 NAS ping 또는 DSM 접속  
- [ ] (선택) 원격 데스크톱으로 상시 PC 접속이 되는지도 확인 — 브리지 LAN 공개 전 **즉시 사용 가능**한 우회  

### 단계 3 — 브리지를 “다른 기기 브라우저”가 쓰게 (개발/설정)

지금 코드는 localhost 전용이라, VPN만으로는 폰 브라우저가 `127.0.0.1`에 닿지 않습니다.

- [ ] 브리지 listen을 LAN 허용으로 변경 (예: `0.0.0.0:17820` 또는 설정 파일화)  
- [ ] Windows 방화벽에서 17820 허용 (VPN/내부망만)  
- [ ] UI의 API 주소가 `127.0.0.1`에 고정된 부분이 있으면 **접속한 호스트 기준**으로 동작하는지 점검  
- [ ] VPN 켠 폰에서 `http://상시PC의내부IP:17820` 접속 테스트  

이 단계까지 오면 **「어디서나 · 어떤 단말기 · 브라우저」** 목표가 VPN 기준으로 달성됩니다.  
(네이티브 앱 스토어 빌드는 필수가 아닙니다.)

### 단계 4 — (선택) HTTPS 북마크 공개

- [ ] 도메인/DDNS, 리버스 프록시, Let’s Encrypt 등 HTTPS  
- [ ] **필수 로그인**(브리지 앞단 또는 앱 자체)  
- [ ] 17820을 인터넷에 직접 노출하지 않기 (443만 공개)  
- [ ] 모바일 화면 점검·필요 시 반응형/PWA  

### 단계 5 — 쓰지 말 것

- [ ] NAS SMB(445)를 인터넷에 상시 개방  
- [ ] 인증 없는 브리지 공개  
- [ ] QuickConnect URL만으로 방송실 앱이 된다고 가정

## 5. 단말기별 사용 모습 (목표 달성 후)

| 단말기 | VPN 경로 | HTTPS 경로 |
|--------|----------|------------|
| **Windows/Mac** | VPN 앱 → 브라우저로 브리지 | 브라우저만 |
| **Android/iOS** | VPN 앱 → 모바일 사파리/크롬 | 브라우저만 (홈 화면 추가 가능) |
| **스토어 앱 빌드** | 불필요 | 불필요 (원하면 나중에 PWA/래퍼) |

CtrlOne(장비 TCP 제어)은 NAS와 무관한 **별도 로컬 앱**이라, 이 원격 웹 계획에 **자동으로 포함되지 않습니다.**  
밖에서의 장비 제어는 별도 논의가 필요합니다.

## 7. 자주 묻는 질문

**Q. NAS에 “외부 접속 주소”가 있는데 그걸 브리지 호스트에 넣으면?**  
A. **상시 PC가 방송실 LAN에 있으면** 넣을 필요 없습니다. 내부 IP가 더 빠르고 안정적입니다.  
밖 **노트북에 브리지를 직접** 띄울 때만 외부 SMB 주소를 검토하고, 가능하면 VPN으로 내부 IP를 쓰는 편이 낫습니다.

**Q. 모바일용으로 따로 빌드해야 하나?**  
A. **필수는 아닙니다.** 웹 UI이므로 브라우저로 충분합니다. 다만 버튼·표가 PC 기준이면 터치 UX 개선은 별도 작업입니다.

**Q. Tailscale / ZeroTier 같은 것도 VPN인가?**  
A. 넓은 의미에서 **메시 VPN**입니다. 공인 IP·포트 포워딩 없이 기기끼리 가상 LAN을 만들어 주어, 자가 호스팅 VPN보다 설정이 쉬운 경우가 많습니다. 방송실 PC + 폰에만 설치해도 “방법 ①”과 같은 효과를 낼 수 있습니다.

**Q. 비용이 드나?**  
A. VPN·내부 사용은 보통 추가 비용 없음(도메인 없이도 가능). HTTPS 공개 시 도메인 비용이 들 수 있음. 미니 PC 전기·구매비는 있음.
